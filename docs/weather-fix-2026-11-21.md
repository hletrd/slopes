# 날씨 결측·관측시각 수정 2026-11-21

운영 데이터 72개 위치 중 67개에 잘못된 마지막 행 `TM--T::00+09:00`가 있었고, 해당 행의 모든 기상값은 `-999`였다. 기상청 응답의 헤더를 숫자 자료로 처리하고 가장 뒤의 행을 무조건 선택한 것이 원인이었다. 최신 요청 시각에 아직 생산되지 않은 자료의 결측 행도 섞였다. 화면은 실제 자료 시각 대신 수집 시각을 표시했다.

수집기는 유효한 날짜·시간의 관측 행만 읽고, 결측 부호·비정상 수치를 `null`로 정규화한다. 전부 결측인 행과 미래 자료는 버리고 나머지는 관측 시각으로 정렬한다. [기상청 공식 명세](https://apihub.kma.go.kr/specs/10-convergence-weather/01-high-res-grid/01-high-res-grid-500m/03-high-res-grid-point-multi-element.yml)의 최대 60분 조회 범위를 지키면서, 생산 지연을 고려해 10분 전까지 5분 간격 자료를 요청한다. 0도·강수량 0·음수 기온은 유효한 값으로 보존한다.

날씨 갱신 작업은 현재 서비스의 자료를 먼저 받아 임시 원본 장애 때 유효한 이전 자료를 유지한다. 새 응답이 전부 결측이면 성공한 갱신으로 취급하지 않는다. 유효한 자료가 하나도 없으면 배포를 중단한다. 리조트 제공 관측점도 보존한다. 기존 API 키는 GitHub Secret에 그대로 두고, 요청 실패 로그에 인증키가 담긴 URL을 출력하지 않는다.

기존 화면과 React 화면은 공통 자료 선택 함수를 사용한다. 잘못된 이전 JSON이 남아 있어도 헤더·결측 행을 건너뛰어 가장 최근의 유효한 관측값을 표시한다. 표시는 한국 시각의 실제 자료 시각을 기준으로 하며, 2시간 넘은 자료에는 오래된 자료 표시를 붙인다. 날씨는 5분마다, 그리고 창이 다시 보일 때 재조회하며 영상 플레이어를 다시 만들지 않는다. 서비스 워커는 날씨 JSON을 캐시하지 않는다. 공유 이미지도 결측값을 숨기고 각 리조트의 자료 시각을 표시한다.

기상청의 매 5분 생산 주기와 GitHub Actions의 실행 시각은 별개다. 점검 당시 5분 cron이 활성화돼 있었지만 실제 예약 실행에는 수 시간 간격이 관찰됐다. 화면은 이 지연을 현재 자료로 표시하지 않고 실제 시각과 오래된 자료 표시로 드러낸다.

회귀 검증: 날씨 Python 테스트 6개, 공통 표시 함수 Node 테스트 4개, 기존 제공처 테스트 7개를 통과했다. TypeScript 검사, 두 정적 사이트 빌드와 React 미리 렌더링을 통과했다. 기존 운영 JSON 정리 시 72개 위치를 보존하면서 잘못된 행 134개를 제거했고, 결측 적설값을 포함한 미리보기 이미지 생성도 확인했다.
